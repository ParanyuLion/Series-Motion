# ประกอบการ์ตูน AI พากย์ไทยจากชิ้นส่วนที่ทดสอบเอง

**สรุปสั้น:** ณ ต.ค. 2026 ยังไม่มี skill หรือ MCP ตัวใดที่ทำ "การ์ตูน AI พากย์ไทย" ได้ครบจบในตัว ผู้ใช้ต้องต่อชิ้นส่วนเองจากสี่ชั้น ชั้นแรกคือการประกอบวิดีโอและคำบรรยาย ซึ่ง Remotion มี Agent Skills อย่างเป็นทางการ (`npx skills add remotion-dev/skills`) ([Remotion](https://www.remotion.dev/docs/ai/skills)) ชั้นที่สองคือการสร้างภาพและวิดีโอ ซึ่งเข้าถึงโมเดลกว่า 1,000 ตัวได้ผ่าน fal.ai MCP ทางการ ([fal docs](https://fal.ai/docs/model-apis/mcp)) หรือผ่าน Runway MCP ที่เปิดเมื่อ 2026-05-27 ([AI Weekly](https://aiweekly.co/alerts/runway-opens-mcp-server-for-chatgpt-claude-cursor-replit)) ชั้นที่สามคือเสียงพากย์ไทย ผู้ที่ยืนยันว่ารองรับไทยจากเอกสารทางการคือ ElevenLabs (เฉพาะ v3/v4) และ Google Gemini-TTS ส่วน Botnoi และ iApp เป็นผู้ให้บริการไทย และมี F5-TTS-THAI เป็นทางเลือกฟรี ชั้นที่สี่คือ lip-sync ซึ่งเป็นจุดเสี่ยงที่สุด เพราะไม่พบการทดสอบภาษาไทยกับเครื่องมือใดเลย และไม่พบ skill หรือ MCP สำหรับ lip-sync เลย หลักฐานเฉพาะภาษาไทยบางมาก ส่วนใหญ่เป็นคำอ้างของผู้ขาย การเริ่มต้นที่สมเหตุสมผลสำหรับ solo creator บน Windows จึงเป็นการทำ pilot 30-60 วินาที พร้อมทดสอบเสียงไทยกับเครื่องมือหลายเจ้า และทดสอบ lip-sync ก่อนลงทุนซื้อเครดิตก้อนใหญ่ รายงานนี้ใช้ "(ข้อสรุปของผู้วิจัย)" กำกับส่วนที่ไม่มีแหล่งอ้างอิงยืนยัน

## Claude skills และ MCP ครอบคลุมชั้นประกอบ สร้างภาพ และเสียง แต่ไม่ครอบคลุมภาษาไทยหรือ lip-sync

ชั้นที่มีเครื่องมือทางการที่สุดคือการประกอบวิดีโอ Remotion เผยแพร่ Agent Skills ที่ติดตั้งด้วย `npx skills add remotion-dev/skills` หรือรับ prompt ตอนรัน `bun create video` ชุดนี้มีคำสั่ง `/remotion-captions` สำหรับคำบรรยาย `/remotion-markup` สำหรับ composition แอนิเมชัน เสียง และฟอนต์ และ `/remotion-multimedia` ([Remotion](https://www.remotion.dev/docs/ai/skills)) หน้าเอกสารนั้นไม่ได้พูดถึง Whisper หรือภาษาไทย ตัวถอดเสียง `@remotion/install-whisper-cpp` ต้องการไฟล์ WAV 16-bit 16 kHz และตัวอย่างในเอกสารใช้โมเดล `medium.en` ที่เป็นอังกฤษล้วน จึงต้องเปลี่ยนเป็นโมเดลหลายภาษาสำหรับภาษาไทย บน Windows ถ้าสตริงเวอร์ชันไม่ใช่ semver จะเกิดข้อผิดพลาด ([Remotion transcribe](https://www.remotion.dev/docs/install-whisper-cpp/transcribe)) สำหรับงานตัดต่อด้วย ffmpeg มี `ffmpeg-mcp-server` ซึ่งรวม ffmpeg-static ไว้ในตัว ผู้ใช้ Windows จึงไม่ต้องติดตั้ง ffmpeg เอง ([Socket](https://socket.dev/npm/package/ffmpeg-mcp-server)) แต่ใบรับรองของเซิร์ฟเวอร์กลุ่มนี้มาจากหน้ารายการ (directory) ไม่ได้เปิดตัว repo ตรวจ

ด้านสร้างภาพและวิดีโอ fal.ai MCP ทางการ (`mcp.fal.ai/mcp` ใช้ API key ผ่าน Authorization header) ทำงานกับ Claude Code ได้ และเข้าถึง Kling, Veo, Seedance ผ่านจุดเดียว ([fal docs](https://fal.ai/docs/model-apis/mcp)) Runway MCP ทางการใช้เครดิต Runway ไม่ต้องมี API key และรวม Gen-4.5, Seedance, Kling 3.0, Veo 3.1 และ Nano Banana Pro ([Runway help](https://help.runwayml.com/hc/en-us/articles/51931843164691-Runway-MCP)) ผู้วิจัยไม่พบ MCP เฉพาะของ Kling เพราะเข้าถึงได้ผ่านสองทางข้างต้น (ข้อสรุปของผู้วิจัย: จึงไม่จำเป็นต้องหา MCP แยก) ส่วน ComfyUI มี MCP ของชุมชนหลายตัว เช่น Comfy-Org/comfy-mcp ([GitHub](https://github.com/Comfy-Org/comfy-mcp)) ขณะที่ MCP ทางการแบบ local/cloud ของ Comfy ถูกบรรยายว่าเป็นการทดสอบแบบปิดหรือ early access โดยแหล่งข้อมูลขัดกันเรื่องสถานะ ([Comfy docs](https://docs.comfy.org/agent-tools/local))

ด้านเสียง ElevenLabs MCP (`uvx elevenlabs-mcp` พร้อม API key) ให้ TTS, speech-to-text, เอฟเฟกต์เสียง และโคลนเสียง ([ElevenLabs blog](https://elevenlabs.io/blog/introducing-elevenlabs-mcp)) แต่โน้ตสองฉบับขัดกันเรื่องสถานะ ฉบับหนึ่งบอกว่า repo นี้ถูกประกาศ deprecated และให้ไปใช้ MCP แบบโฮสต์ `https://api.elevenlabs.io/v1/mcp` ที่ใช้ OAuth ([GitHub](https://github.com/elevenlabs/elevenlabs-mcp)) ผู้ใช้ควรเปิดหน้า repo ตรวจเองก่อนติดตั้ง ส่วน README ไม่ได้ครอบคลุม Claude Code โดยตรง (ข้อสรุปของผู้วิจัย: น่าจะใช้ `claude mcp add` ได้ แต่ยังไม่ยืนยัน)

skill สำหรับสตอรีบอร์ดมีอยู่ แต่เป็นของชุมชนขนาดเล็กและมุ่งไปที่โมเดลวิดีโอเฉพาะ เช่น seedance-storyboard ของ elementsix (MIT เน้นผู้ใช้จีน) ([sourcepulse](https://www.sourcepulse.org/projects/29109188)) และ videoagent-director ของ pexoai ที่เปลี่ยนไอเดียเป็นแผน 3-9 ช็อต ([claudemarketplaces](https://claudemarketplaces.com/skills/pexoai/pexo-skills/videoagent-director)) ส่วนโอเพนซอร์สเต็มไปป์ไลน์ที่ใกล้เคียงที่สุดคือ ViMax (HKUDS, MIT) ที่มี workflow Idea2Video และ Script2Video พร้อมเอเจนต์ผู้เขียนบท ผู้กำกับ และผู้ออกแบบตัวละครเพื่อรักษาความสม่ำเสมอข้ามช็อต ([DEV review](https://dev.to/dibi8/vimax-review-agentic-multi-scene-video-generation-from-hkuds-5dc1)) แต่จำนวนดาวที่รายงาน (3.5k-5.5k) ขัดกันและผู้วิจัยไม่ได้เปิด repo หลักตรวจ MoneyPrinterTurbo (MIT) เป็นตัวสร้างวิดีโอสั้นที่โตแล้ว แต่ใช้ฟุตเทจสต็อกเป็นแกน จึงไม่เหมาะกับการ์ตูน ([Verdent](https://www.verdent.ai/guides/moneyprinterturbo-github)) ช่องว่างสำคัญคือไม่พบ skill สำหรับภาษาไทย, lip-sync, Whisper/คำบรรยายไทย หรือ skill ที่เชื่อมทั้งสายงานเข้าด้วยกัน และผู้วิจัยยังไม่ได้ค้น anthropics/skills, awesome-claude-skills, skills.sh, smithery หรือ mcp.so จึงไม่อาจสรุปได้ว่า "ไม่มีจริง" ควรตรวจที่เหล่านี้ก่อนเขียน skill เอง

## โมเดลวิดีโอเปลี่ยนเร็ว Sora ปิดแล้ว และตัวเลขราคาขัดกันระหว่างแหล่ง

Sora 2 ปิดแอปเมื่อ 26 เม.ย. 2026 และปิด API เมื่อ 24 ก.ย. 2026 ข้อมูลใดที่อ้าง Sora ถือว่าล้าสมัย ([tech-insider](https://tech-insider.org/best-ai-video-generator-2026/)) ผู้เล่นปัจจุบันที่มี API ได้แก่ Kling 3.0, Seedance 2.0/2.5, Veo 3.1 และ Gemini Omni, Wan 3.0, MiniMax Hailuo/H3, Runway Gen-4.5 และ Luma Ray3.x ตารางด้านล่างสรุปตัวที่น่าสนใจสำหรับการ์ตูน ราคาต่อนาทีมาจากบล็อกรวบรวมและแหล่งของผู้ขายซึ่งขัดกันเอง (เช่น Veo 3.1 รายงานตั้งแต่ $0.10 ถึง $0.75 ต่อวินาที) ต้องยืนยันกับหน้าราคาทางการ

|---|---|---|---|
| Kling 3.0 | สูงสุด 15 วินาที | ~$15-20 ต่อนาที | Elements ล็อกหน้า/เสื้อผ้า/เสียงด้วยภาพอ้างอิงถึง 4 ภาพ; lip-sync ในตัวไม่ระบุไทย |

(ข้อมูลตารางจาก [tech-insider](https://tech-insider.org/best-ai-video-generator-2026/) และ [buildmvpfast](https://www.buildmvpfast.com/api-costs/ai-video)) Seedance 2.5 (คลิป 30 วินาที) ถูกรายงานโดยแหล่งเดียวและวันที่เปิดตัวขัดกัน (มิ.ย. หรือ ก.ค. 2026) จึงยังไม่ยืนยัน Kling 4.0 Flash อยู่ในการเข้าถึงแบบจำกัดเมื่อ ก.ย. 2026 ([Kling blog](https://kling.ai/blog/kling-3-subject-binding-character-consistency)) แหล่งส่วนใหญ่เป็นผู้ขายต่อหรือเนื้อหาสปอนเซอร์ (เช่นบทความของ Higgsfield) และไม่มีแหล่งใดจัดอันดับคุณภาพสไตล์อนิเมะหรือ 2D โดยตรง ดังนั้นการทดสอบสไตล์ของตัวเองเป็นสิ่งที่ขาดไม่ได้

ความสม่ำเสมอของตัวละครมีแนวปฏิบัติค่อนข้างชัด คือสร้าง character sheet ด้วยโมเดลภาพ (Nano Banana หรือ Seedream) แล้วใช้เป็นภาพอ้างอิงให้โมเดลวิดีโอที่มีฟีเจอร์อ้างอิงในตัว ([invideo](https://invideo.io/faq/how-do-you-create-a-character-reference-sheet-using-nano/)) Nano Banana 2 รักษาตัวละครหลักได้ 1-2 ตัวพอใช้ แต่ 3 ตัวขึ้นไปยาก ([Zilliz](https://zilliz.com/ai-faq/how-many-consistent-characters-can-nano-banana-2-maintain-across-a-workflow)) ทางโอเพนซอร์สคือเทรน character LoRA บน Flux (Kontext turnaround sheet) ([RunComfy](https://www.runcomfy.com/comfyui-workflows/flux-kontext-character-turnaround-sheet-lora)) ผู้วิจัยสรุปว่าดีไซน์ 2D แบนที่มีสีชัดและพร็อพน้อยจะเพี้ยนน้อยกว่า (ข้อสรุปของผู้วิจัย) ไม่มีผลทดสอบอิสระเรื่องความสม่ำเสมอในสไตล์การ์ตูนข้ามโมเดล

## เสียงพากย์ไทยมีตัวเลือกจริงสี่ตระกูล แต่ไม่มีใครวัดความเป็นธรรมชาติของภาษาไทยอย่างอิสระ

ElevenLabs รองรับไทย (`th`) เฉพาะโมเดล Eleven v4, v4 Turbo และ v3 ไม่รวม Multilingual v2, Flash v2.5 หรือ Turbo v2.5 ซึ่ง Turbo v2.5 ถูก deprecated และตัวแทนอย่าง Flash v2.5 ก็ไม่มีไทย ([ElevenLabs models](https://elevenlabs.io/docs/overview/models)) นัยทางปฏิบัติคือต้องใช้โมเดลรุ่นแพงกว่าสำหรับไทย Google Gemini-TTS ระบุ th-TH เป็น GA และรองรับ style prompt พร้อมแท็กอารมณ์ เช่น [sigh] [whispering] และมีโหมดหลายผู้พูด แต่เอกสารเตือนให้ยืนยันภาษาไทยเป็นรายโมเดล ([Google Cloud docs](https://docs.cloud.google.com/text-to-speech/docs/gemini-tts)) Azure มีเสียงไทย 3 เสียง (Premwadee, Niwat, Achara) ([json2video](https://json2video.com/ai-voices/azure/languages/thai/)) โดยมีรายงานปี 2022 (อาจล้าสมัย) ว่า Premwadee มีช่วงหยุดคั่นระหว่างคำที่ไม่ต้องการ ([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/1146448/(text-to-speech)-break-rate-pitch-is-a-problem-wit)) ผู้ให้บริการไทยคือ Botnoi Voice (REST API ต้องสมัครสมาชิกก่อนจึงได้ API key) ([Botnoi docs](https://botnoigroup.com/botnoivoice/doc/api-user-guide)) และ iApp ที่ระบุ ~1 บาทต่อ 400 ตัวอักษร (ตัวเลขที่ผู้ให้บริการรายงานเอง) ([iApp](https://iapp.co.th/blog/ai-voice-technology-thailand-guide)) ทางฟรีและรันเองคือ F5-TTS-THAI (`pip install f5-tts-th` ใช้เสียงอ้างอิง 2-8 วินาที) ที่โมเดลการ์ดยอมรับว่าออกเสียงผิดบางคำและข้อความยาว และคำต่างประเทศต้องเขียนทับศัพท์ ([HF](https://huggingface.co/VIZINTZOR/F5-TTS-THAI)) ใบอนุญาตไม่ชัด (cc-by-4.0 บนโมเดลการ์ด แต่บางแหล่งรายงานน้ำหนักฐาน F5-TTS ว่าไม่อนุญาตเชิงพาณิชย์ ซึ่งยังไม่ได้ตรวจ) ก่อนใช้เชิงพาณิชย์ต้องตรวจเอง Fish Audio ไม่ระบุไทยในเอกสารปัจจุบัน ขัดกับข้อมูลเก่าจาก OpenRouter ([Fish docs](https://docs.fish.audio/developer-platform/models-pricing/models-overview))

เรื่องคุณภาพ หลักฐานอ่อนที่สุด รีวิวภาษาไทยสองชิ้นเห็นต่างกัน ชิ้นหนึ่งว่า ElevenLabs ดีสำหรับโคลนเสียงและพากย์ไทย อีกชิ้นว่าไทย "ไม่สมบูรณ์" (ดูจากสนิปเพ็ตเท่านั้น) ([Lemon8](https://www.lemon8-app.com/@nitaextra/7533989228322046480?region=th), [IDM Council](https://www.idmcouncil.com/blog/elevenlabs-ai-voice-marketing/)) รีวิวทั่วไปของ ElevenLabs พบการออกเสียงผิดเป็นครั้งคราวและตัวเลข/คำย่อต้องเขียนเป็นเสียงอ่าน ([Capterra](https://capterra.com/p/10013392/ElevenLabs/reviews/)) ส่วนคำอ้างเรื่องวรรณยุกต์และคำลงท้าย ครับ/ค่ะ/นะ ของ ElevenLabs และ AnySpeech เป็นข้อความการตลาดของผู้ขาย ([ElevenLabs Thai](https://elevenlabs.io/text-to-speech/thai), [AnySpeech](https://anyspeech.io/thai-text-to-speech)) งานวิชาการ ThonburianTTS ของมหิดลรายงาน WER 25.72% ([Mahidol](https://repository.li.mahidol.ac.th/handle/123456789/115796)) แต่เป็นงานวิจัยและไม่ได้เทียบกับบริการเชิงพาณิชย์ ผู้วิจัยจึงแนะนำให้ทดสอบเทียบเอง (ข้อสรุปของผู้วิจัย: ใช้สคริปต์ 30 วินาทีเดียวกันที่มีคู่เสียงวรรณยุกต์ คำยืม ตัวเลข และคำลงท้าย แล้วแก้คำเพี้ยนด้วยการเขียนทับศัพท์หรือเว้นวรรคเพื่อคุมการตัดคำ)

สำหรับเสียงตัวละคร ไม่พบหลักฐานว่ามีคลังเสียงเด็ก สัตว์ หรือการ์ตูนภาษาไทยในเครื่องมือใดเลย Typecast มีเสียงการ์ตูนแต่ไม่ระบุไทย ([Typecast](https://typecast.ai/text-to-speech/)) ElevenLabs voice changer (speech-to-speech) ไม่รองรับไทย เพราะใช้โมเดล 29 ภาษา ([ElevenLabs docs](https://elevenlabs.io/docs/product/speech-synthesis/speech-to-speech)) ทางที่น่าจะเชื่อถือได้สุดคือโคลนเสียงจากคลิปนักพากย์จริง (ElevenLabs IVC หรือ F5-TTS-THAI) (ข้อสรุปของผู้วิจัย) ส่วน RVC และโปรแกรมเปลี่ยนเสียงสำหรับไทยไม่มีหลักฐานเลย เรื่องต้นทุน ElevenLabs ฟรีไม่มีสิทธิ์เชิงพาณิชย์ และ Starter (~$5-6 ต่อเดือน ~30 นาที) ขึ้นไปมี ([ElevenLabs pricing](https://elevenlabs.io/pricing)) แหล่งต่างกันเรื่องราคาแพ็กเกจ Creator ($11 ในหน้าราคาที่ผู้วิจัยฉบับหนึ่งอ่าน กับ ~$22 ในบล็อกรวบรวม) จึงต้องดูหน้าราคาจริง ค่าเสียงโดยรวมต่ำ (เซนต์ถึงไม่ถึงดอลลาร์ต่อนาทีที่เสร็จ) ต่างจากค่าวิดีโอที่เป็นต้นทุนหลัก

## Lip-sync คือความเสี่ยงอันดับหนึ่ง เพราะไม่มีใครทดสอบกับเสียงไทย

โมเดลที่รับ "ภาพ + เสียง" แล้วทำให้ตัวละครพูดจัดการหน้าการ์ตูนและหน้าไม่ใช่มนุษย์ได้ ได้แก่ OmniHuman 1.5, Kling AI Avatar 2, Hedra Character-3, MiniMax H3 Max lip sync และ Sync-3 Avatar ขณะที่ Sync Lipsync แบบวิดีโอต่อวิดีโอถูกรายงานว่าจำกัดกับตัวละครสมจริง ([Scenario](https://help.scenario.com/en/articles/lip-sync-models-overview)) OmniHuman 1.5 ระบุราคา $0.12 ต่อวินาทีที่ BytePlus ([BytePlus](https://www.byteplus.com/de/product/OmniHuman)) Hedra Character-3 คิด 6 เครดิตต่อวินาที แต่ Trustpilot ~2.1/5 เรื่องการเรียกเก็บเงินและซัพพอร์ต ([fluxnote](https://fluxnote.io/guides/hedra-ai-review)) Kling 3.0 lip-sync ในตัวรองรับอังกฤษ จีนกลาง ญี่ปุ่น เกาหลี สเปน ไม่มีไทย แต่เครื่องมือ lip-sync แบบหลังประมวลผลของ Kling รับไฟล์เสียงที่อัปโหลดและระบุว่าใช้ได้กับตัวละคร 2D/3D ([Kling lip sync](https://kling.ai/th/feature/lip-sync)) Sync Labs อ้างโมเดลสำหรับภาษามีวรรณยุกต์รวมไทย (คำอ้างของผู้ขาย ยังไม่ยืนยัน) ([sync.so](https://ai.sync.so/lip-sync-tonal-languages-model)) การทดสอบของ Tom's Guide จัดอันดับ Hedra แรก Kling ที่สอง แต่เป็นการทดสอบภาษาอังกฤษกับใบหน้าสมจริง ([Tom's Guide](https://tomsguide.com/ai/ai-image-video/lip-sync-battle-i-put-3-leading-ai-video-tools-to-the-test)) ทางโอเพนซอร์สมี LatentSync, MuseTalk, Wav2Lip แต่แหล่งเป็นบล็อกผู้ขายและไม่มีการทดสอบกับหน้าการ์ตูน ([sync.so](https://sync.so/blog/the-best-free-open-source-lipsync-tools-2)) CapCut/Dreamina มี lip-sync ตัวละครอนิเมชันพร้อมเสียง AI กว่า 350 เสียงและมีหน้าไทย แต่ไม่มีข้อมูลคุณภาพภาษาไทย ([CapCut](https://www.capcut.com/th-th/resource/ai-lip-sync))

ข้อสรุปของผู้วิจัย (ยังไม่ได้ทดสอบ) คือโมเดลที่ขับด้วยเสียงแปลงพลังงานเสียงเป็นการอ้าปากค่อนข้างไม่ขึ้นกับภาษา ไทยจึงอาจใช้ได้ในเชิงจังหวะเปิด-ปากแม้ไม่อยู่ในรายการ ทางออกที่ปลอดภัยคือทำเสียงไทยก่อน สร้างภาพนิ่ง/วิดีโอแบบไม่มีเสียง แล้วค่อยใส่ lip-sync ที่ขับด้วยเสียงเป็นรายช็อต แทนการพึ่งโมเดลที่สร้างเสียงเองอย่าง Veo/Kling/Wan ที่ไทยยังไม่ยืนยัน สำหรับตัวละครมาสคอต 2D แบน การสลับสไปรต์ปากตามแอมพลิจูดใน Remotion/ffmpeg เป็นแผนสำรองที่แน่นอนกว่า (ข้อสรุปของผู้วิจัย)

## Workflow เริ่มต้นบน Windows ต้องออกแบบให้ล้มเหลวถูกและทดสอบก่อนลงทุน

ไม่พบเคสศึกษาจากครีเอเตอร์ไทยที่ตรวจสอบได้เลย ทั้งช่อง YouTube บล็อก Pantip และกลุ่ม Facebook แม้ค้นด้วยภาษาไทย สิ่งที่พบคือไปป์ไลน์ทั่วไปภาษาอังกฤษ (สคริปต์ ภาพตัวละครสม่ำเสมอ การเคลื่อนไหวเบา TTS ประกอบใน CapCut) จากสรุปผลค้น ไม่ได้เปิดอ่านหน้าเต็ม ([Cal Poly Housing](https://grandavehousing.calpoly.edu/news/ai-youtube-video-creation-a), [Shotstack](https://shotstack.io/learn/youtube-automation-ai/)) และตัวอย่างไทยเพียงชิ้นเดียวคือนิตยสาร "ขายหัวเราะ" ฉบับการ์ตูนมุกที่ AI สร้างทั้งเรื่องและภาพ ซึ่งเป็นภาพนิ่งไม่มีเสียงพากย์ ([Thairath](https://www.thairath.co.th/money/business_marketing/marketing/2676591)) ขั้นตอนต่อไปนี้จึงเป็นข้อเสนอของผู้วิจัยทั้งหมด ไม่ใช่ workflow ที่ยืนยันแล้ว

ลำดับที่แนะนำสำหรับผู้สร้างคนเดียวคือ หนึ่ง เขียนเรื่องและสคริปต์ไทยภาษาพูดสั้น ๆ เอง ใช้ LLM ช่วยร่าง เพราะนโยบายการสร้างรายได้ต้องการความคิดสร้างสรรค์ดั้งเดิม สอง ล็อกตัวละครด้วย character sheet และบล็อกสไตล์ในทุก prompt สาม ทดสอบเสียงไทยหนึ่งวัน (ElevenLabs v3/v4, Gemini-TTS, Botnoi และ F5-TTS-THAI ฟรี) ด้วยสคริปต์ 30 วินาทีเดียวกัน สี่ เคลื่อนไหวอย่างประหยัด ใช้แพน/ซูมและคลิป image-to-video สั้น ๆ เน้นพากย์เล่าเรื่องในฉากแอ็กชัน และเก็บช็อตหน้าพูดให้สั้นจนกว่าจะทดสอบ lip-sync ไทยแล้ว ห้า ประกอบด้วย Remotion skills (หรือ CapCut/DaVinci Resolve) ใช้ฟอนต์ไทยที่วางสระและวรรณยุกต์ถูก เช่น Sarabun, Noto Sans Thai หรือ Prompt และตรวจการเรนเดอร์ จุดนี้เป็นความรู้ทั่วไปของผู้วิจัยที่ไม่มีแหล่งอ้างอิง ผู้วิจัยยังตั้งข้อสังเกตว่า Remotion ต้องตัดบรรทัดคำบรรยายไทยด้วย PyThaiNLP (`word_tokenize` engine newmm) ([PyThaiNLP](https://export.arxiv.org/pdf/2312.04649)) แต่พฤติกรรมของฟอนต์ไทยและการตัดคำใน Remotion ยังไม่มีเอกสารยืนยัน หก เผยแพร่ pilot 30-60 วินาที แล้วบันทึกเครื่องมือ ใบอนุญาต และ prompt เป็นหลักฐานงานต้นฉบับ

ด้านนโยบาย YouTube เปลี่ยนชื่อ "repetitious content" เป็น "inauthentic content" เมื่อ 15 ก.ค. 2025 สไลด์ภาพนิ่งและเนื้อเรื่องแม่แบบที่มีบทบรรยายน้อยไม่เข้าเกณฑ์ ส่วน AI ใช้ได้เมื่อเห็นวิสัยทัศน์สร้างสรรค์ของผู้สร้าง เช่นการสร้างภาพตัวละครและเรื่องที่ตนคิดเอง ([YouTube Help](https://support.google.com/youtube/answer/1311392)) หน้านั้นไม่ได้กล่าวถึงเสียงพากย์ AI โดยเฉพาะ กฎการเปิดเผยกำหนดสำหรับเนื้อหาสมจริงเท่านั้น และยกเว้นภาพเคลื่อนไหวที่ไม่สมจริง สคริปต์/ชื่อเรื่อง และการโคลนเสียงตัวเองสำหรับพากย์ ([YouTube Help](https://support.google.com/youtube/answer/14328491)) การ์ตูนสไตล์ไลซ์จึงน่าจะอยู่ในข้อยกเว้น แต่ซีรีส์ที่ใช้แม่แบบเดียวกันซ้ำ ๆ เสี่ยงต่อกฎ inauthentic (ข้อสรุปของผู้วิจัย) TikTok ให้ติดป้ายเนื้อหา AI สมจริงตามประกาศเดือน ก.ย. 2023 ([TikTok Newsroom](https://newsroom.tiktok.com/new-labels-for-disclosing-ai-generated-content?lang=en)) แต่กฎ 2026 ของ TikTok และ Meta ยังไม่ได้ตรวจ ควรโคลนเฉพาะเสียงตัวเองหรือนักพากย์ที่ยินยอมเป็นลายลักษณ์อักษร (ลิงก์เงื่อนไขการโคลนของ ElevenLabs คืน 404 จึงไม่ได้ตรวจเงื่อนไข consent)

## ช่องว่างหลักฐานที่ต้องรู้ก่อนลงทุน

## บทสรุป

ข้อค้นพบที่เปลี่ยนมุมมองมากที่สุดคือ ส่วนที่ "Claude ช่วยได้จริงและมีของทางการ" คือการประกอบ สั่งโมเดลสร้างภาพ/วิดีโอ และสร้างเสียง ส่วนสองจุดที่กำหนดความสำเร็จของงานพากย์ไทย คือคุณภาพวรรณยุกต์ของ TTS และ lip-sync กับเสียงไทย กลับเป็นจุดที่ไม่มีทั้ง skill และหลักฐานทดสอบ ทางลดความเสี่ยงที่ถูกที่สุดจึงเป็นการทดสอบสั้น ๆ สองอย่างก่อนทุกอย่าง คือทดสอบเสียงไทยเทียบกันหนึ่งวัน และทดสอบ lip-sync ไทยหนึ่งช็อตบนตัวละครของตัวเอง

ในเชิงรูปแบบงาน ช่องว่างที่พบชี้ว่าการเริ่มด้วยตัวละครแบน เสียงพากย์เล่าเรื่อง และการสลับสไปรต์ปากเอง น่าจะเสถียรกว่าการไล่ตามโมเดลวิดีโอที่พูดได้ในตัว และผู้ใช้อาจได้ประโยชน์จากการเขียน skill ของตัวเองสำหรับสคริปต์/สตอรีบอร์ดไทย การกำหนดเสียงต่อตัวละคร และคำบรรยายไทย (ตัดคำด้วย PyThaiNLP) เมื่อยืนยันแล้วว่ายังไม่มี skill ที่ดีกว่าใน skills.sh หรือรายการ awesome
