# ให้ Claude Code วาดการ์ตูนทุกช็อตด้วยโค้ด

**คำตอบสั้น:** วิธีที่เป็นไปได้และมีเครื่องมือรองรับดีที่สุดบน Windows คือ **Remotion (React + SVG) ควบคุมโดย Claude Code พร้อม Remotion Agent Skills** โดยให้ตัวละครเป็น "ตุ๊กตาชิ้นส่วน" (rig) ที่เขียนเป็น SVG แล้วขยับด้วยฟังก์ชันที่ผูกกับเลขเฟรม และใช้เสียงบรรยายไทยจาก TTS เป็นตัวกำหนดความยาวของแต่ละช็อต ทางเลือกคือ HyperFrames (HTML + GSAP, Apache-2.0) ซึ่งสร้างมาให้เอเจนต์ใช้โดยตรง ([Remotion docs](https://www.remotion.dev/docs/ai/claude-code); [HyperFrames](https://github.com/heygen-com/hyperframes)) ทั้งสองตัวเรนเดอร์ด้วย headless Chrome จับภาพทีละเฟรมแล้วต่อเป็น MP4 ผลคือได้วิดีโอที่ซ้ำได้เหมือนเดิมทุกครั้ง ข้อควรรู้ที่สุดคือหลักฐานยังบางสองจุด หนึ่ง ไม่มีใครยืนยันได้ว่าโพสต์ Instagram ของ @promptkub ใช้เครื่องมืออะไร (อ่านโพสต์ไม่ได้เพราะติดหน้า login) สอง ไม่พบตัวอย่างที่ตรวจสอบได้ว่า LLM เขียนโค้ดให้ตัวละคร "เดินจริง" จนจบเรื่อง ตัวอย่างที่มีเกือบทั้งหมดเป็น motion graphics และ explainer ดังนั้นขั้นตอนต่อไปนี้ส่วนที่เกี่ยวกับ walk cycle และ lip-sync ไทยเป็น **ข้อเสนอของผู้วิจัย (ข้อสรุปจากการอนุมาน ยังไม่ทดสอบ)** ผู้ใช้ควรทำ pilot สั้น ๆ 10-15 วินาทีก่อนลงทุนทำทั้งเรื่อง ส่วนค่าใช้จ่ายด้านเสียงต่ำ (ระดับเซนต์ถึงไม่ถึงดอลลาร์ต่อนาที) และ Remotion ใช้ฟรีสำหรับบุคคลทั่วไป

## ทำไมโค้ดวาดจึงเลือก Remotion เป็นแกนหลัก และ HyperFrames เป็นตัวสำรอง

Remotion เรนเดอร์โดยเปิด Chromium แบบ headless แล้วจับภาพหน้าจอทีละเฟรม (วิดีโอ 30 วินาทีที่ 30 fps เท่ากับ 900 ภาพ) ([timewell.jp](https://timewell.jp/en/columns/remotion-claude-code-programmatic-video)) เอกสารทางการมีขั้นตอนใช้กับ Claude Code คือ `npx create-video --yes --blank my-video` แล้ว `npm run dev` จากนั้นสั่งเอเจนต์ ([Remotion docs](https://www.remotion.dev/docs/ai/claude-code)) และมีชุด Agent Skills ทางการ (`npx skills add remotion-dev/skills`) ครอบคลุมคำบรรยาย เสียง ฟอนต์ และการเรนเดอร์ ([Remotion skills](https://www.remotion.dev/docs/ai/skills)) โน้ตจากทั้งสองงานวิจัยย้ำว่าคำสั่งติดตั้งในบล็อกต่าง ๆ ไม่ตรงกัน (บางที่ใช้ `npx remotion skills add`) ให้ยึดหน้าเอกสารทางการ และให้บอกเอเจนต์ให้เช็กเอกสารปัจจุบัน เพราะโมเดลอาจจำ API รุ่นเก่า ([Tella](https://www.tella.com/blog/how-to-use-remotion-agent-skills-with-claude-code.md))

HyperFrames (HeyGen) เขียนด้วย HTML + CSS + GSAP แล้วเรนเดอร์ด้วย Puppeteer และ FFmpeg ต้องใช้ Node 22 ขึ้นไป CLI ออกแบบให้เอเจนต์เรียกโดยไม่ต้องโต้ตอบ ใบอนุญาต Apache-2.0 ([HyperFrames](https://github.com/heygen-com/hyperframes)) ข้อได้เปรียบคือ HTML/GSAP เป็นโค้ดที่ LLM คุ้นมาก และใบอนุญาตผ่อนคลายกว่า ข้อเสียคือโปรเจกต์ใหม่ กับยังไม่มีการทดสอบเทียบ Remotion กับ HyperFrames สำหรับแอนิเมชันตัวละครโดยตรง (ข้อสรุปของผู้วิจัย: ถ้าไม่มีเหตุผลด้านใบอนุญาตให้เริ่มที่ Remotion เพราะชุมชนและเอกสารใหญ่กว่า) ส่วน Motion Canvas (MIT) เหมาะกับไดอะแกรมมากกว่าตัวละคร ([AlternativeTo](https://alternativeto.net/software/motion-canvas/about)) Rive, Theatre.js, Lottie เขียนมือ และ Manim ไม่เหมาะกับโจทย์ "ให้ LLM เขียนทุกอย่าง" เพราะต้องพึ่งตัวแก้ไขภาพหรือออกแบบมาเพื่อคณิตศาสตร์ (ข้อสรุปของผู้วิจัย ไม่ใช่ข้อเท็จจริงที่ยืนยันจากการทดสอบ) ผู้ใช้ Windows ต้องมี Node LTS ขั้นต่ำตามที่เครื่องมือต้องการ และอาจติดตั้ง FFmpeg เพิ่มเฉพาะงานหลังประมวลผล (ข้อสรุปของผู้วิจัย เอกสารทางการไม่มีหมายเหตุเฉพาะ Windows และหน้า Windows ของ Remotion คืน 404 ตอนค้น)

## ตัวละครเดินได้ด้วยโครงกระดูก JSON และฟังก์ชันที่ผูกกับเฟรม

รูปแบบที่ LLM ทำได้เสถียรที่สุดคือ "โค้ดรันไทม์ทั่วไป + ข้อมูลตัวละครเป็น JSON" แทนการให้โมเดลวาดใหม่ทุกช็อต skill ชื่อ `character-rigging` ในรีโป OpenMontage สอนแนวทางนี้ คือแยกตัวละครเป็นชิ้นส่วนอิสระ กำหนดจุดหมุน (pivot) ในพิกัดเดียวกับงานภาพ ใช้ลำดับพ่อ-ลูก (หัวผูกกับลำตัว) กำหนดช่วงหมุนต่อข้อต่อ กำหนดเลขเลเยอร์ชัดเจนแทนลำดับใน SVG และแยกปาก ตา ลูกตา พร็อพเป็นชิ้นต่างหาก พร้อมสคีมา JSON (`character_id`, `parts`, `joints`) ([SkillsCat](https://skills.cat/skills/calesthio/openmontage/character-rigging)) skill นี้แนะนำ GSAP ที่ใช้ `svgOrigin` กำหนด pivot ตรง ๆ เพราะ `transform-origin` ของ SVG ต่างกันตามเบราว์เซอร์ และใน Remotion ต้องให้ GSAP ถูกขับด้วยเลขเฟรมปัจจุบัน ไม่ใช่ `requestAnimationFrame` ([claudeskills.info](https://claudeskills.info/skills/calesthio/openmontage/svg-character-animation/)) ข้อควรระวังคือรายการ skill ชุดนี้ถูกระบุว่าไม่มีการยืนยันผู้เผยแพร่ ([skills-hub](https://skills-hub.ai/skills/openmontage-svg-character-animation)) ต้องอ่าน SKILL.md ก่อนติดตั้งทุกครั้ง และใช้เป็นแนวอ้างอิงมากกว่าการพึ่งพา

สูตรการเคลื่อนไหวต่อไปนี้เป็นความรู้มาตรฐานที่ผู้วิจัยเสนอ **ไม่มีแหล่งอ้างอิงที่ยืนยันและยังไม่ได้ทดสอบ** แต่เป็นสิ่งที่ LLM เขียนได้ตรงไปตรงมา ข้อต่อใช้กลุ่ม `<g transform="translate rotate">` ซ้อนกัน มุมต้นขา = A·sin(phase) โดย phase = 2π·เฟรม/คาบ ขาอีกข้างเลื่อนครึ่งรอบ เข่างอ = max(0, sin(phase+offset)) แขนแกว่งสวนด้วยแอมพลิจูดครึ่งหนึ่ง ตัวกระเด้งขึ้นลงสองครั้งต่อรอบ ใช้ IK แบบสองท่อนด้วยกฎโคไซน์สำหรับเท้าติดพื้นและมือชี้ ใช้ easing แบบ spring สำหรับการเหวี่ยงเกินแล้วดึงกลับ และใช้ตัวสุ่มที่ตั้งค่า seed เพื่อให้เรนเดอร์ซ้ำได้เหมือนเดิม ฉากหลัง กล้อง และพาราแลกซ์ก็ทำด้วยหลักเดียวกัน คือเป็นฟังก์ชันของเลขเฟรม (กล้อง = การแปลงผกผันของทั้งฉาก, พาราแลกซ์ = ตำแหน่งกล้อง × ค่าความลึก, แสงเป็นรูปหลายเหลี่ยมไล่เฉดโปร่งใส) ซึ่งทั้งหมดอยู่ในหมวดข้อสรุปของผู้วิจัยเช่นกัน ฉากฝูงตัวละครเยอะควรลดรายละเอียดหรือใช้ Canvas เพราะ SVG ที่มีกลุ่มซ้อนหลายร้อยชั้นช้า

เรื่องแหล่งภาพ ทางที่เสี่ยงน้อยคือให้ Claude เขียน SVG ของตัวละครเอง (คุมสไตล์และ pivot ได้) ส่วนฉากหลังและพร็อพที่ไม่ขยับจะใช้ภาพจาก AI ก็ได้ ถ้าต้องการงานศิลป์ละเอียดจากภาพ AI ต้องแยกเลเยอร์ก่อน เช่น Qwen-Image-Layered (แยกเป็น 2-8 เลเยอร์ RGBA) ([GitHub](https://github.com/QwenLM/Qwen-Image-Layered)) หรือ img2rig ที่ใช้ DINO+SAM ([img2rig](https://github.com/SSnemo/img2rig)) แต่จะมีรูโหว่ที่ข้อต่อ ต้องวาดชิ้นส่วนให้ซ้อนทับ (ข้อสรุปของผู้วิจัย) ความสม่ำเสมอของตัวละครจากโมเดลภาพเชื่อถือได้เพียง 1-2 ตัวต่อฉาก ([Zilliz](https://zilliz.com/ai-faq/how-many-consistent-characters-can-nano-banana-2-maintain-across-a-workflow)) สำหรับฉากแอ็กชันที่ตัวละครเยอะ ให้สร้างตัวประกอบจากฟังก์ชัน rig เดียวกันแล้วแปรผันด้วย seed (สี ขนาด จังหวะก้าว) ซึ่งเป็นข้อเสนอของผู้วิจัย

## เสียงบรรยายไทยมาก่อน แล้วให้ความยาวเสียงกำหนดความยาวช็อต

หลักการที่ Remotion รองรับตรง ๆ คือ `calculateMetadata` อ่านความยาวไฟล์เสียงแล้วคืนค่า `durationInFrames` ได้ และ props ที่ส่งตอนเรนเดอร์ทับค่าเริ่มต้นได้ ([Remotion dynamic metadata](https://www.remotion.dev/docs/dynamic-metadata.md)) เอกสารเปลี่ยนวิธีอ่านความยาวจาก `parseMedia` ไปเป็น Mediabunny และหน้าเอกสารไม่มีตัวอย่างเสียงโดยเฉพาะ จึงต้องทดสอบกับ Remotion รุ่นที่ติดตั้งเอง ให้ปัดเศษขึ้นเพื่อไม่ให้ท้ายประโยคถูกตัด

ตัวเลือกเสียงไทยที่ยืนยันจากเอกสารทางการมีสี่ตระกูล ElevenLabs รองรับไทยเฉพาะ Eleven v3 และ v4 (ไม่รวม Multilingual v2 หรือ Flash v2.5) ([ElevenLabs models](https://elevenlabs.io/docs/overview/models)) Google Gemini-TTS ระบุ th-TH และรองรับคำสั่งสไตล์กับหลายผู้พูด ([Google Cloud](https://docs.cloud.google.com/text-to-speech/docs/gemini-tts)) Azure มีเสียงไทย 3 เสียง (Premwadee, Niwat, Achara) ([json2video](https://json2video.com/ai-voices/azure/languages/thai/)) และมี Botnoi, iApp รวมถึง F5-TTS-THAI ที่ฟรีแต่ออกเสียงผิดบางคำและมีเรื่องใบอนุญาตที่ต้องตรวจ ([HF](https://huggingface.co/VIZINTZOR/F5-TTS-THAI)) ไม่มีการวัดความเป็นธรรมชาติของไทยแบบอิสระเทียบกันเลย รีวิวสองชิ้นขัดกัน (ชิ้นหนึ่งว่าดี อีกชิ้นว่า "ไม่สมบูรณ์") ([Lemon8](https://www.lemon8-app.com/@nitaextra/7533989228322046480?region=th), [IDM Council](https://www.idmcouncil.com/blog/elevenlabs-ai-voice-marketing/)) จึงควรทดสอบเอง ด้วยสคริปต์ 30 วินาทีเดียวกันที่มีคู่เสียงวรรณยุกต์ คำยืม ตัวเลข และคำลงท้าย (ข้อเสนอของผู้วิจัย)

ถ้าต้องการให้คำบรรยายหรือท่าทางผูกกับคำ ต้องมีเวลาระดับคำ ElevenLabs `convert-with-timestamps` คืนเวลาระดับตัวอักษร แต่เอกสารไม่ยืนยันว่ารองรับไทยหรือ v3 ([ElevenLabs API](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps)) Azure มีเหตุการณ์ `WordBoundary` ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-speech-synthesis#subscribe-to-synthesizer-events)) แต่มีรายงานค่าเป็นศูนย์ในบาง SDK ([MS Q&A](https://learn.microsoft.com/en-sg/answers/questions/1651510/azure-text-to-speech-wordboundary-event-always-ret)) ส่วน Gemini-TTS ไม่มีการกล่าวถึง timestamp ในเอกสารที่อ่าน ทางสำรองคือถอดเสียงด้วย Whisper ผ่าน `@remotion/install-whisper-cpp` (ต้องเปลี่ยนเป็นโมเดลหลายภาษาที่ไม่ใช่ `.en`) ([Remotion](https://www.remotion.dev/docs/captions/transcribing)) หรือโมเดลไทยอย่าง Thonburian ที่รายงาน WER 7.42 แต่รุ่นที่มี timestamp ความแม่นเวลาลดลง (WER 15.57) ([HF](https://huggingface.co/biodatlab/whisper-th-medium-timestamp)) เนื่องจากรู้ข้อความบทอยู่แล้ว ผู้วิจัยแนะนำใช้ ASR เฉพาะหาเวลา แล้วแมปกลับไปที่ข้อความบทต้นฉบับ (ข้อเสนอ ยังไม่ทดสอบ) และตัดคำไทยด้วย `Intl.Segmenter('th')` ([MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)) หรือ PyThaiNLP

## ปากขยับ คำบรรยายไทย เสียงประกอบ และใบอนุญาต

สำหรับการขยับปาก หลักฐานเดียวที่ตรงกับ pipeline นี้คือ Rhubarb Lip Sync ให้ปาก 9 รูปแบบจากไฟล์เสียง โดยโหมด PocketSphinx รองรับอังกฤษเท่านั้น ส่วนโหมด phonetic ไม่ผูกภาษาแต่แม่นยำน้อยกว่า ([Rhubarb](https://github.com/despossivel/rhubarb-lip-sync)) และไม่มีหลักฐานทดสอบกับไทย วิทยานิพนธ์จุฬาฯ "Thai LIP-SYNC" ใช้ forced alignment กับสคริปต์ไทยแล้วแปลงหน่วยเสียงเป็น viseme และรายงานผลดี ([Thai LIP-SYNC](https://doi.nrct.go.th/ListDoi/listDetail/10.14457%2FCU.the.2011.1311)) ข้อเสนอของผู้วิจัยสำหรับการ์ตูนแบน (ยังไม่ทดสอบ) คือเริ่มจากวิธีที่ง่ายและแน่นอนที่สุด คือคำนวณแอมพลิจูด RMS ต่อเฟรมจากเสียงพากย์ แล้วสลับสไปรต์ปาก 3-4 แบบตามระดับเสียง เพราะวรรณยุกต์ไม่เห็นเป็นรูปปาก ความต่างที่เห็นได้หลัก ๆ คือสระกลม (อู โอ) กับสระกว้าง (อา แอ) โปรเจกต์ The Stickverse ใช้การกระพือปากตามความดังเช่นกัน แต่ผู้เขียนเองยอมรับว่าหยาบ ([HackerNoon](https://hackernoon.com/i-built-a-poor-mans-pixar-using-python-gemini-and-my-sense-of-humor))

คำบรรยายไทยใช้ `@remotion/google-fonts` โดยระบุ weights และ subsets ชัดเจน ([Remotion loadFont](https://www.remotion.dev/docs/google-fonts/load-font)) ผู้ทดสอบรายหนึ่งพบว่าอักษรสูงอย่างไทยโดนตัดที่ line-height 1.1 และต้องราว 1.6 ([SuttaCentral](https://discourse.suttacentral.net/t/testing-for-line-height-with-tall-scripts/6196)) ข้อเสนอของผู้วิจัย: ใช้ Noto Sans Thai, Sarabun หรือ Prompt, line-height 1.5-1.7, ห้ามใส่ letter-spacing, เรนเดอร์ภาพนิ่งทดสอบคำที่มีสระซ้อนวรรณยุกต์ (เช่น "ผู้ปั้น" "ที่นี่") และตรวจในผลเรนเดอร์จริง ไม่ใช่แค่ Studio ส่วนเสียงประกอบ Pixabay ใช้เชิงพาณิชย์ได้โดยไม่ต้องให้เครดิตแต่ห้ามขายซ้ำเป็นไฟล์เสียงเดี่ยว Freesound ต้องกรองเป็น CC0 หรือบันทึกเครดิตรายไฟล์ ([Cinevva](https://app.cinevva.com/guides/free-sound-effects-music)) ElevenLabs SFX ฟรีต้องให้เครดิต แผนจ่ายเงินไม่ต้อง ([ElevenLabs](https://elevenlabs.io/ko/sound-effects/commercial)) การลดเสียงเพลงขณะมีเสียงบรรยายทำใน Remotion ได้ด้วย `interpolate` ที่ส่งเป็น `volume` ([Remotion volume](https://www.remotion.dev/docs/audio/volume)) เนื่องจากรู้เวลาบรรยายล่วงหน้า จึงเป็นฟังก์ชันแน่นอนในการเรนเดอร์เดียว

เรื่องใบอนุญาต Remotion ฟรีสำหรับบุคคล องค์กรไม่แสวงกำไร และบริษัทแสวงกำไรที่มีพนักงานไม่เกิน 3 คน บริษัทใหญ่กว่าต้องซื้อ (Creators $25 ต่อที่นั่งต่อเดือน ขั้นต่ำ 3 ที่นั่ง) ([Remotion pricing](https://www.remotion.dev/docs/license/pricing)) ใบอนุญาตเป็นแบบ source-available ไม่ใช่โอเพนซอร์สเต็มตัว และมีการระบุว่าจะเปลี่ยนเล็กน้อยใน Remotion 5.0 ([Remotion license](https://remotion.dev/license)) ให้ตรวจก่อนใช้เชิงพาณิชย์ GSAP ฟรีทุกการใช้งานรวมเชิงพาณิชย์ แต่ห้ามใช้สร้างเครื่องมือ animation builder ที่แข่งกับ Webflow ([Webflow](https://webflow.com/blog/gsap-becomes-free)) Spine: ฝัง runtime ได้ฟรี แต่ผู้ใช้ปลายทางของซอฟต์แวร์ที่ใช้ต้องมีไลเซนส์ Spine ของตัวเอง และข้อความใบอนุญาต runtime ขัดกันระหว่างแหล่ง ให้อ่าน LICENSE ในรีโป ([Esoteric forum](https://it.esotericsoftware.com/forum/d/4984)) Live2D Cubism เป็นกรรมสิทธิ์ ฟรีเมื่อรายได้ต่ำกว่า 10 ล้านเยนต่อปี ([Live2D](https://help.live2d.com/en/?p=2181)) Rive runtime รายงานว่าเป็น MIT แต่ผู้วิจัยไม่เห็นไฟล์ LICENSE ตรง ๆ ([Rive](https://rive.app/docs/runtimes)) ข้อสรุปของผู้วิจัยคือไม่ต้องใช้ Spine, DragonBones หรือ Live2D สำหรับ pipeline "โค้ดวาดล้วน" เพราะ rig JSON + SVG หลีกเลี่ยงเรื่องใบอนุญาตและให้ LLM แก้ได้ทุกไฟล์ HyperFrames Apache-2.0 ([HyperFrames](https://github.com/heygen-com/hyperframes)) ส่วนใบอนุญาต F5-TTS-THAI และน้ำหนักฐานต้องตรวจเองก่อนใช้เชิงพาณิชย์ และผู้วิจัยยังไม่ได้ตรวจเงื่อนไขการโคลนเสียงของ ElevenLabs ควรโคลนเฉพาะเสียงตัวเองหรือผู้ที่ยินยอมเป็นลายลักษณ์อักษร ด้านนโยบาย YouTube เปลี่ยนชื่อ "repetitious content" เป็น "inauthentic content" เมื่อ 15 ก.ค. 2025 และยอมรับ AI ที่มีวิสัยทัศน์สร้างสรรค์ของผู้สร้าง ([YouTube Help](https://support.google.com/youtube/answer/1311392)) ซีรีส์ที่ใช้แม่แบบเดียวกันซ้ำ ๆ อาจเสี่ยง (ข้อสรุปของผู้วิจัย)

## ขั้นตอนแนะนำตั้งแต่บทถึงเรนเดอร์ และแผน pilot

ลำดับต่อไปนี้ประกอบจากแหล่งที่อ้างข้างต้นและเป็น **ข้อเสนอของผู้วิจัย** ไม่ใช่ workflow ที่มีใครยืนยันว่าใช้ได้ครบทั้งสาย โครงสร้างกลางที่ชื่อและหลักคือ spec file ที่มี timeline กับค่าคงที่ (แนวของ [zerofuturetech](https://zerofuturetech.substack.com/p/generate-videos-with-claude-code)) และจุดขออนุมัติบทก่อนเขียนโค้ด (แนวของ [sabrina.dev](https://www.sabrina.dev/p/5-insane-claude-code-video-prompts))

| ขั้น | สิ่งที่ทำ | ผลลัพธ์ |
|---|---|---|
| 1. เตรียมเครื่อง | ติดตั้ง Node LTS, สร้างโปรเจกต์ด้วย `npx create-video --yes --blank`, ติดตั้ง Remotion skills, เปิด `npm run dev` | โปรเจกต์ที่พรีวิวได้ |
| 2. บทและสตอรีบอร์ด | เขียนบทพูดไทยสั้น ๆ เอง ให้ Claude แตกเป็น `shots.json` (ผู้พูด ข้อความ แอ็กชัน กล้อง SFX) และหยุดรออนุมัติ | บทที่อนุมัติแล้ว |
| 3. ไฟล์กำหนดศิลป์ | เขียนพาเล็ตสี สไตล์เส้น ความหนา ฟอนต์ ลงในไฟล์ค่าคงที่เดียว | ตัวละครไม่เพี้ยนข้ามช็อต |
| 4. ตัวละคร rig | ให้ Claude เขียนชิ้นส่วน SVG + `rig.json` (pivot พ่อลูก ช่วงหมุน เลเยอร์ ปาก 3-4 แบบ) ครั้งเดียว แล้วนำเข้าใช้ทุกช็อต ห้ามวาดใหม่ต่อช็อต | คอมโพเนนต์ `Character({rig, pose})` |
| 5. ไลบรารีท่าทาง | `walk(phase)`, `gesture(name,t)`, `Mouth`, `Camera`, `Parallax`, `Particles` เป็นฟังก์ชันของเฟรม | ฟังก์ชันที่เรียกซ้ำได้ |
| 6. ตรวจท่าก่อนเรนเดอร์ | เรนเดอร์ภาพนิ่งด้วย `npx remotion still` หลายเฟรม (เช่น walk cycle 8 เฟรม) ให้ Claude ดูภาพแล้วแก้ข้อต่อเพี้ยน | contact sheet ผ่านเกณฑ์ |
| 7. เสียงไทย | สร้างเสียงทีละช็อตด้วย TTS ที่ทดสอบแล้ว บันทึก mp3 + ความยาว + เวลาคำ แคชตามแฮชของ (ข้อความ+เสียง+โมเดล) | `public/audio/*.mp3` + manifest |
| 8. ประกอบ | `calculateMetadata` คำนวณความยาวช็อตจากเสียง (เผื่อ 0.3 วินาที) แล้วใช้ `<Sequence>` ต่อช็อต; ปากขยับตามแอมพลิจูด; คำบรรยายไทยตัดคำ | พรีวิวครบเรื่อง |
| 9. เสียงประกอบ | วาง SFX ตามเฟรม/คำ ลดเพลงขณะพูด บันทึกแหล่งและใบอนุญาตใน `credits.json` | มิกซ์เสียงในเรนเดอร์เดียว |
| 10. เรนเดอร์ | `npx remotion benchmark` หาค่า concurrency แล้วเรนเดอร์ MP4 แยกรายฉากถ้ายาว | ไฟล์ MP4 |

ปัญหาที่พบซ้ำคือภาพทุกอย่างเริ่มพร้อมกันเพราะลืมกำหนด `from` ใน `<Sequence>` ([timewell.jp](https://timewell.jp/en/columns/remotion-claude-code-programmatic-video)) และต้องสั่งให้ LLM เรียกฟังก์ชันตามลายเซ็นที่ระบุ ห้ามเขียน transform อิสระ (ข้อเสนอของผู้วิจัย)

**แผน pilot 10-15 วินาที (ข้อเสนอของผู้วิจัย ยังไม่ทดสอบ)** ใช้ตัวละครเดียวและฉากเดียว วันแรกทำตัวละครหนึ่งตัว (ขั้น 3-4) พร้อมท่าเดินและท่ายืนนิ่ง ตัดสินด้วยภาพนิ่ง 8 เฟรมว่าเดินดูเป็นธรรมชาติหรือไม่ วันที่สองทำฉากเดียวที่มีกล้องเคลื่อนหนึ่งครั้งและพาราแลกซ์สองชั้น พร้อมบรรทัดบรรยายไทยสองประโยค ทดสอบ TTS ไทย 2-3 เจ้าด้วยบทเดียวกัน (ElevenLabs v3, Gemini-TTS, Azure หรือ Botnoi) และเรนเดอร์ปากตามแอมพลิจูด เกณฑ์ผ่านที่ควรตั้งคือ ข้อต่อไม่เพี้ยนหรือลอย เสียงไม่ออกเสียงผิดจนฟังไม่รู้เรื่อง คำบรรยายไม่ถูกตัดสระและวรรณยุกต์ และเวลาเรนเดอร์กับจำนวนรอบแก้ต่อช็อตอยู่ในระดับที่ยอมรับได้ ให้บันทึกเวลาจริง จำนวนรอบ และโทเค็นที่ใช้ เพราะไม่มีแหล่งใดมีตัวเลขเวลาหรือต้นทุนต่อนาทีของงานแบบนี้ (ตัวเลขนาทีใด ๆ จะเป็นการเดา) ถ้าผ่านจึงขยายเป็นหลายช็อต แล้วค่อยปรับสไตล์เป็นของตัวเองโดยแก้ไฟล์กำหนดศิลป์และ rig เท่านั้น ทางเลือกคู่ขนานคือทำ pilot เดียวกันบน HyperFrames เพื่อเทียบว่า Claude เขียนตัวละครด้วยตัวใดได้ดีกว่า

## ช่องว่างหลักฐานที่ต้องรู้ก่อนเชื่อรายงานนี้

ช่องว่างแรกและใหญ่สุดคือโพสต์ Instagram ของ @promptkub (instagram.com/p/DecTQRbOcXU/) อ่านไม่ได้เพราะหน้าล็อกอิน ไม่พบหน้าใดที่พูดถึง "promptkub", "Stickocalypse" หรือ "The Last Farm" ดังนั้น **เครื่องมือที่โพสต์นั้นใช้ยังไม่ยืนยัน** Remotion หรือ HTML/Canvas เป็นเพียงการเดาจากระบบนิเวศปี 2026 วิธีปิดช่องว่างคือเปิดโพสต์ด้วยบัญชีที่ล็อกอิน อ่านคำบรรยายและคอมเมนต์ที่ปักหมุด และเช็กโปรไฟล์หรือลิงก์ประกอบ ช่องว่างที่สอง **ไม่พบตัวอย่างที่ตรวจสอบได้ว่า LLM เขียนโค้ดให้การ์ตูนที่ตัวละครเดินจริงจนจบ** ตัวอย่างและบทเรียนที่พบเป็นงาน motion graphics, explainer, logo reveal ([OpenReplay](https://blog.openreplay.com/making-videos-claude-code-remotion/)) และรีโปเชิงเรื่องเล่า (ClaudeAnimationBase, The Stickverse, videocreation) เป็นโปรเจกต์ขนาดเล็กมาก (ดาวเป็นหลักหน่วยถึงพัน ตัวเลขจากรายการรวบรวม ไม่ได้ตรวจบน GitHub) ไม่มี benchmark คุณภาพ SVG ตัวละครของ Claude ข้ออ้างที่ว่าต้องมีวงจรเรนเดอร์-ดู-แก้ภาพ จึงเป็นข้อสรุปของผู้วิจัย ช่องว่างที่สาม ภาษาไทยเฉพาะทางบางมาก ไม่มีการทดสอบ Rhubarb กับไทย ไม่ยืนยันว่า ElevenLabs v3 คืน timestamp ไทยถูกต้อง ไม่มีผลวัดความคลาดเคลื่อนเวลาคำไทยของ Whisper ตัวใด และไม่มีตัวอย่าง Thai caption ใน Remotion ช่องว่างที่สี่คือรายละเอียด Windows การติดตั้ง ความเร็วเรนเดอร์ และต้นทุนจริงต่อนาทีที่ไม่มีแหล่งใดให้ไว้ รวมถึงชื่อโมเดลบางตัว (เช่น "Gemini 3.8 Flash TTS") ที่มาจากหน้าสรุปเพียงแหล่งเดียวและต้องตรวจซ้ำ

## บทสรุป

สิ่งที่เปลี่ยนมุมมองจากงานก่อนหน้า (ที่เน้นประกอบวิดีโอจากโมเดล gen ภาพ/วิดีโอ) คือ การให้ Claude Code วาดทุกช็อตด้วยโค้ดแลกกับการควบคุมที่แน่นอน ตัวละครไม่เพี้ยน เรนเดอร์ซ้ำได้ ไม่มีค่าโมเดลวิดีโอ และ lip-sync ไทยกลายเป็นเรื่องเรียบง่ายที่ทำเองได้ด้วยแอมพลิจูด แทนที่จะรอโมเดลที่ยังไม่มีใครทดสอบกับเสียงไทย ราคาที่ต้องจ่ายคือภาระอยู่ที่การออกแบบ rig และไลบรารีท่าทางที่ต้องสร้างและตรวจเอง ซึ่งเป็นจุดที่ยังไม่มีหลักฐานว่า LLM ทำได้ดีโดยไม่ต้องแก้ซ้ำหลายรอบ

ผู้ใช้จึงควรมองว่านี่คือการทดลองสองสัปดาห์ ไม่ใช่สูตรสำเร็จ ลงทุนในสิ่งที่ใช้ซ้ำได้ (rig JSON, ไฟล์กำหนดศิลป์, ไลบรารีท่าทาง, manifest เสียง) เพราะเมื่อปรับเป็นสไตล์ตัวเอง ส่วนที่ต้องแก้มีเพียงไฟล์เหล่านั้น และเก็บบันทึกเครื่องมือ ใบอนุญาต และ prompt ไว้เป็นหลักฐานงานต้นฉบับตามนโยบายแพลตฟอร์ม
